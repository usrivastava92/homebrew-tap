# Homebrew Tap

Homebrew tap for apps and CLI tools published by `usrivastava92`.

## Available packages

### wakeup

A tiny, auditable `caffeinate`-compatible keep-awake CLI. Cross-platform. Zero dependencies.

```bash
brew install usrivastava92/tap/wakeup
```

### gtv-desktop-remote

Desktop remote for Google TV and Android TV.

```bash
brew install --cask usrivastava92/tap/gtv-desktop-remote
```

The cask uses Homebrew's declarative `postflight_steps` to remove the quarantine
flag from the installed app. Use a current Homebrew version that supports this
DSL. Future cask updates are generated by the
[`gtv-desktop-remote` release workflow](https://github.com/usrivastava92/gtv-desktop-remote/blob/main/.github/workflows/release.yml);
keep installation-hook changes in sync with its
[`render-homebrew-cask.mjs` generator](https://github.com/usrivastava92/gtv-desktop-remote/blob/main/scripts/render-homebrew-cask.mjs).

The [Homebrew Cask Cookbook](https://docs.brew.sh/Cask-Cookbook#stanza-flight_steps)
documents `run` as an executable plus literal arguments and `{{appdir}}` as an
install-time token. This preserves custom application directories, including
spaces, and removes only `com.apple.quarantine` recursively after installation.
It does not run the command during uninstallation.

### Postflight regression CI

The `Homebrew postflight smoke` workflow updates official stable Homebrew on an
Apple Silicon macOS runner and records `brew --version` and `brew config`.
It loads the actual cask with Homebrew's Ruby loader and executes its actual
postflight artifact, including Homebrew's sandbox, against a temporary fixture
app. It checks warning-free loading, recursive quarantine removal, a custom
app directory containing spaces, preservation of other attributes/adjacent
apps, repeat installation and uninstall-phase isolation. No release download,
real application installation/removal or `/Applications` write is involved.
The test uses Homebrew's internal Ruby artifact API only in CI; the shipped
cask uses the documented DSL. Homebrew 7.0.9 was the current official stable
release when this smoke was added; CI follows updated stable Homebrew rather
than retaining an obsolete runtime.

If the old `Calling postflight is deprecated` warning persists, first run
`brew update`, then inspect the exact `.rb` path printed in the warning. The
current tap has `postflight_steps` at line 12, not `postflight`. Compare that
file and its tap checkout (`git -C "$(brew --repository usrivastava92/tap)"
log -1 --oneline`) with
[the current cask](https://github.com/usrivastava92/homebrew-tap/blob/main/Casks/gtv-desktop-remote.rb).
A warning pointing to a file that still contains `postflight` identifies a
stale/local cask or installed metadata, not a new warning from the current
definition. A Homebrew version too old to recognise `postflight_steps` is a
different compatibility failure; update Homebrew instead of restoring the
deprecated stanza.

## Install

Tap once and install any package:

```bash
brew tap usrivastava92/tap
brew install wakeup
brew install --cask gtv-desktop-remote
```
